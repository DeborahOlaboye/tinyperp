# Agent instructions

Briefing for coding agents working in this repository. `README.md` is the full reference for humans; this file is what you need to change the code safely.

## What this is

Tinyperp is a Scaffold-HBAR template: leveraged long and short positions on Hedera, settled against a liquidity pool.

- Prices: Chainlink Data Feeds, optionally cross-checked against the Supra push oracle.
- Collateral: one Hedera Token Service (HTS) token, used through its ERC-20 facade.
- Settlement at expiry: booked on the Hedera Schedule Service, so no keeper is needed.

It is a Yarn workspace with two packages: `packages/hardhat` (Solidity, Hardhat, `hardhat-deploy`) and `packages/nextjs` (Next.js App Router, RainbowKit, wagmi, viem, DaisyUI).

Use the package manager the project was created with (`packageManager` in the root `package.json`, or the lockfile). Examples use `yarn`; with npm, swap `yarn <script>` for `npm run <script>`.

## Commands

```bash
# Local development (separate terminals)
yarn hardhat:chain                              # Hardhat node forking Hedera testnet, port 8545
yarn hardhat:deploy --network localhost         # TestUSD, PerpEngine, mock oracles, markets, pool seed
yarn next:dev                                   # http://localhost:3000
yarn hardhat:set-price --market HBAR/USD --price 0.12   # move a mock price

# Checks: run all of these before you call a change done
yarn hardhat:compile
yarn hardhat:test
yarn lint
yarn hardhat:check-types
yarn next:check-types
yarn next:build

# Hedera testnet
yarn hardhat:account:import
yarn hardhat:deploy --network hederaTestnet
yarn hardhat:smoke --network hederaTestnet      # end-to-end run with HashScan links
yarn hardhat:verify PerpEngine testnet
```

`yarn hardhat:deploy` without `--network localhost` targets the in-process `hardhat` network, which does not emulate HTS. Always pass a network.

Tests fork Hedera testnet, so they need a network connection and take about a minute.

## Rules that must keep holding

1. **Solvency.** `collateral.balanceOf(engine) == poolAssets + totalMargin + totalClaimable`, and `reservedAssets <= poolAssets`. Any change to money movement must keep both true. `expectSolvent` in `test/PerpEngine.test.ts` checks them; call it in every new test that moves money.
2. **Every position reserves its maximum profit at open.** `_payoutAt` caps the payout at `margin + reserved`. Do not raise a payout without raising the reservation.
3. **Settlement never depends on the recipient.** Payouts go through `_pay`, which credits `claimable` when a transfer fails. Do not replace it with `safeTransfer`: an account that dissociates from the token would then block its own liquidation.
4. **Scheduling is best effort.** Calls to the Schedule Service are low-level and their failure is tolerated. Opening, closing and liquidating must work when `0x16b` is missing or rejects the call.
5. **Chainlink sets the price; Supra can only stop a trade.** A stale or failing Supra feed is ignored, never trusted and never allowed to freeze a market.
6. **State changes come before external calls**, and every external entry point that moves value is `nonReentrant`.
7. **Engine parameters have no setters.** They are fixed at deployment on purpose. If a task needs a tunable, discuss it rather than adding a setter.

## Hedera details

- Inside the EVM, `msg.value` and balances are in **tinybars** (8 decimals). Over JSON-RPC, `value` is in **weibars** (18 decimals). `config.autoSettleFee` is in tinybars. Use `toRpcValue` from `tinyperpConfig.ts` when sending it, in scripts and in the frontend.
- An account must be **associated** with an HTS token to receive it. Users call `associate()` on the token address. The engine associates itself in its constructor.
- HTS amounts are **`int64`**. Check before casting.
- System contracts **return a response code** instead of reverting. `22` is success. Check it and revert with a typed error that carries the code.
- `createFungibleToken` is **payable**: the creation fee is `msg.value`.
- The contract that calls `scheduleCall` **pays for the scheduled execution** and must hold the HBAR for it.
- Booking a schedule costs about **1.41 million gas**, and `scheduleCall` burns everything it is given when that is too little. Always forward a bounded amount (`config.scheduleCallGas`), never the transaction's remaining gas. An `autoSettle` open needs a gas limit of at least 2.2 million.
- **`block.timestamp` is the block's first-transaction time** and can be up to two seconds behind the second a scheduled call runs in. Do not book a call at the exact second a time check starts passing; the engine adds `SETTLE_DELAY`.
- The local fork emulates HTS but **not** the Schedule Service. Unit tests install `MockScheduleService` at `0x16b` with `setCode`.

## Common tasks

**Add a market.** Add an entry to `markets` for the network in `tinyperpConfig.ts`, then run the deploy command. Script `02` lists only markets that are not listed yet. For a live network you need the Chainlink feed address, and the Supra pair index if it should be cross-checked.

**Change a fee or limit.** Edit `ENGINE_CONFIG` in `tinyperpConfig.ts` and redeploy. Update the expected numbers in `test/PerpEngine.test.ts` and the worked example in `README.md`.

**Add an oracle.** Add a reader to `OracleLib` that returns an 18-decimal price and enforces freshness, then call it from `PerpEngine._markPrice`. Add a mock under `contracts/mocks/` and cover the stale, invalid and deviating cases.

**Change payout maths.** Edit `_payoutAt` and `_settle`. Add a test with hand-computed numbers; do not derive the expected value from the contract's own formula.

**Change the frontend.** Screens get everything through props: `tp` (the result of `useTinyperp`), `actions` (`useTinyperpActions`), `now`, `busy`, `run` and `go`. Do not call wagmi from a screen.

- To show new on-chain data, add the read to the right batch in `useTinyperp` and return it. Keep reads batched: one `useCalls` per group.
- To send a new transaction, add it to `useTinyperpActions` with an explicit gas limit from `GAS` in `utils/tinyperp`, and call it from the screen with `run(() => actions.thing(), "What happened.")`. `run` handles the busy state and the toasts.
- Anything the UI computes about money (entry price, payout, liquidation, market status) must come from `utils/tinyperp`, which mirrors the contract's integer arithmetic. If you change the contract's maths, change it there too.
- Amounts stay `bigint` until they are formatted. Parse user input with `parseCollateral`.
- A call that carries HBAR needs `toRpcValue` (tinybars to weibars). A balance read over JSON-RPC needs `fromRpcValue` before it goes back into a contract call.
- HTS allowances are `int64`: never approve `maxUint256`. Use `APPROVAL_AMOUNT`.
- Styling: static styles are classes in `tinyperp.css` (all prefixed `tp-`, scoped under `.tp-root`); only data-dependent values go in inline styles. Colours come from `C` in `ui.tsx` or the CSS variables.
- Markets and positions can be unpriced (stale or halted oracle). Every screen must render that state rather than assume a price.

The scaffold's own hooks (`useScaffoldReadContract`, `useScaffoldWriteContract` in `packages/nextjs/hooks/scaffold-hbar`) still work and power the Debug Contracts page.

## Style

| Style | Use |
| --- | --- |
| `UpperCamelCase` | types, components, contracts |
| `lowerCamelCase` | variables, functions |
| `CONSTANT_CASE` | constants |
| `NN_snake_case.ts` | Hardhat deploy files |

- Solidity: custom errors, not revert strings. NatSpec on every external function. Internal and private functions start with `_`.
- TypeScript: prefer `type` over `interface`, let types be inferred where they can be.
- Frontend: imports use the `~~` alias. Use `@scaffold-hbar-ui/components` for `Address`, `Balance` and inputs, and DaisyUI classes for layout. Add `"use client"` to pages that use hooks.
- Comments say why, not what.
- Never commit `.env` files or private keys. `packages/hardhat/.env` holds the encrypted deployer key and is ignored by Git.
